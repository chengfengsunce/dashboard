# 需求表格与管理员移除

## 2026-11-20 状态操作修正
用户将行操作明确为“完成”，替代此前误解的“删除”：GitHub Issue 更新为 `closed/completed`，成功后自动从进行中移入已完成，不隐藏或删除记录。沿用管理员鉴权、10 条分页和状态筛选；旧同步数据不能撤销刚完成的状态。

实施顺序：先用临时回归测试验证现有删除行为不符合要求，再修改 Worker、按钮与弹窗并更新部署说明；验证成功/失败、刷新保留、分页收缩及手机布局后，以中文说明提交推送。下方为此前版本的设计记录。

## 已确认设计
- 需求列依次为编号、需求、所属项目、提出人、时间，末列提供删除操作。
- 每页 10 条，翻页查看；列表和页面不使用竖向滚动，长标题链接到完整需求。
- 新增时选择项目并填写提出人，创建时间由 GitHub 记录；旧需求显示原作者账号。
- 仅管理员可移除，二次确认；保留 GitHub Issue，以 `dashboard-hidden` 标签软删除，可移除标签恢复。
- 保持公开提交和粘贴图片；管理员密钥仅放在 Worker Secret，不写入页面和浏览器存储。

## 实施计划
1. 在临时目录用 Node 标准库测试 Worker 的元数据、授权、软删除和 CORS；用 Python 标准库测试同步字段与分页。先确认现有实现失败。仓库目前没有测试框架，不增加测试依赖或常驻测试文件。
2. 修改 `worker/worker.mjs`：将项目及提出人作为结构化元数据存入中央需求仓库；增加管理员验证的 DELETE 路由，为原始 Issue 添加隐藏标签，不执行 GitHub 删除。
3. 修改 `scripts/sync_github.py`：同步全部需求，保存编号、创建时间、所属项目、提出人，隐藏标签保持原样供页面过滤。
4. 修改 `index.html`：以 10 行表格替换卡片，关联项目筛选、页码重置与页数收缩；表单添加项目、提出人；删除弹窗二次确认并临时输入管理员密钥，成功后立即移除。
5. 更新 `DEPLOY_AUTO_SUBMIT.md`，说明 ADMIN_TOKEN、恢复方法及原有接口尚未部署时的限制。运行临时回归测试、Python 语法检查、浏览器布局检查、`git diff --check`；仅提交本次文件，以中文说明提交并推送现有 main 分支。

## 验收
- 23 条需求分为 10、10、3 条；筛选后回到第一页，删除最后一页最后一条时页码自动收缩。
- 提交记录仍只进入最近进展，不混入需求表或完成率。
- 旧需求缺少真实姓名时不编造；新需求在立即刷新和定时同步后均保留项目、提出人和创建时间。
- 缺失或错误管理员密钥、跨站请求、其他账号仓库均不能移除需求；密钥不出现在数据文件或日志中。
- 软删除不会在下次同步恢复；恢复标签后可重新出现。
- 桌面与窄屏均没有页面竖向滚动，翻页控件可见。
