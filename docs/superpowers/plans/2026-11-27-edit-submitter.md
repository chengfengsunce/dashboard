# 修改提出人

**目标：** 点击需求列表中的提出人姓名，读取当前姓名后修改并保存，刷新后保留，完成通知使用保存后的姓名。

**方案：** 沿用现有弹窗和公开看板的来源／仓库约束，新增独立的GET／PATCH提出人接口。服务端合并原Issue的 `dashboard-meta.submitter`，保留正文、图片、草稿、其他字段及需求状态。修改前检查源更新时间，冲突时提示重新读取，避免旧页面覆盖新数据。前端以本机暂存覆盖尚未更新的静态快照，源数据追上后移除暂存。

**范围：** 只增加“提出人”编辑，不自动改真实姓名，不从括号备注推断收件人；由用户确认新值。单击姓名或键盘打开，保存和取消明确区分；失败保留输入。复用原通知读取元数据逻辑，编辑不发送通知。
